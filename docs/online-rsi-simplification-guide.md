日期：2026-10-16
状态（更新至 2026-10-18）：P1（批次 A、B）及 P2（批次 C、D）已完成。批次 C 通过 314 项全量测试；批次 D 通过主 agent 审查和 323 项全量测试验收（含 Docker，0 跳过）。批次 E 尚未实施。
P1 后续补修：第 5 步循环与超大工具输出保护通过 308 项回归；真实单题复验在第 4 步服务故障中断，详见 [补修与复验记录](step5-loop-fix-validation.md)。P2 独立记录见 [批次 C 验收](online-rsi-phase-c-review.md)与[批次 D 验收](online-rsi-phase-d-review.md)。
目标：项目只保留在线逐题 RSI，移除原批量实验流程及其专属支持代码。

本文按当前用户确认的范围编写，覆盖历史方案中“同时保留 native 与 online”及“通过原实验三项门槛后再精简”的范围要求。原实验门槛不再是本次框架清理的前置条件；在线候选接任的验收条件继续保留。

## 1. 精简后的功能边界

唯一运行闭环：

```text
活动版本 H_v 首次执行任务 T_i
  -> 独立评分，冻结首次结果，整理公开反馈
  -> 使用 H_v 执行步骤 1、2 的诊断
       -> skip：记录正常跳过，继续使用 H_v
       -> improve：完成步骤 3～7
            -> 步骤 3 声明并冻结验收计划
            -> 步骤 4 实现候选
            -> 步骤 5 独立加载候选执行检查
            -> 步骤 6、7 更新描述和历史
            -> 宿主验收并持久化不可变决策
                 -> 接受：接任 H_(v+1)
                 -> 拒绝：继续使用 H_v
  -> 活动版本执行 T_(i+1)，并承担后续诊断和改进
```

保留任务执行者、改进者和候选父版本为同一活动版本的约束。候选必须经过独立检查；跳过、拒绝和基础设施中断有不同状态语义。

移除范围：整批 H0 基线、递归/固定改进者双轨道、归档排名选择、同起点探针、val/test 分阶段评测、原三项门槛、最终四版本比较和固定轨迹行为回放。

这里删除的是原实验控制流程。在线仍使用固定 SICA 七步定义、角色提示、工具权限、委员会和预算规则，相关上游来源继续保留。

## 2. 优先级与执行原则

| 优先级 | 目的 | 范围 | 完成标准 |
|---|---|---|---|
| P0 必须先落实 | 确定在线契约与历史边界 | 功能约束、旧运行保存、新控制合同、验收基准 | 后续清理不会放宽在线验收或冒用旧运行身份 |
| P1 优先实施 | 整体移除原流程 | 专属文件、CLI、报告、归档分析、回放、对应测试 | 生产入口只支持在线运行和在线报告，无原流程悬空引用 |
| P2 随后实施 | 收敛共享代码 | 在线分支、预算、任务选择、摘要、重复实现、测试接口 | 在线闭环和恢复语义保持，代码路径减少 |
| P3 可选实施 | 减少历史兼容和额外耦合 | 旧上下文预算、数据范围、预留检查项、无效接口 | 每项有明确契约调整和验证，收益足以抵消迁移成本 |

优先级表示价值和依赖顺序，不等同于风险等级。P1、P2 内部按可验证批次完成，每批同步处理调用方和测试。不要先删除模块、随后长期保留失效导入。

## 3. P0：保留在线行为，明确迁移边界

### P0-1 在线必须保持的能力

- [x] 任务顺序冻结，恢复不能按结果重新筛题或更换顺序。
- [x] 每步诊断有成功且非空的归档分析角色报告，报告与步骤、角色身份及公开证据绑定。
- [x] 正常 skip 只完成两步，不执行编码、委员会或候选检查，不产生接任版本。
- [x] 步骤 3 的验收计划在实现前冻结；步骤 5 不能临时改变验收标准。
- [x] 只有步骤 4 可以修改 Harness 源码、配置和测试；步骤 6、7 只更新允许的文档。
- [x] 候选独立加载、独立评分；首次作答结果和候选复测结果分开保存。
- [x] 当前题不退化，且满足已声明的修复或机制判据，才允许接任。
- [x] 被接受的版本实际承担下一题及下一轮改进，不能隐式回到 H0。
- [x] 评分失败可以仅补评分，不再次生成任务答案；恢复不重复提案或重复接任。
- [x] 凭据、评分器内部数据及未来任务信息不进入公开归档或模型上下文。
- [x] 模型/服务身份、token 计量、计费合同、故障暂停和原生资源限制保持。

### P0-2 控制代码身份与历史运行

[core.py](../src/mini_swe_rsi/core.py) 的 `improvement_contract()` 和 [online.py](../src/mini_swe_rsi/online.py) 的 `_control_manifest()` 冻结实现摘要。即使只删除死代码，旧在线运行也可能因摘要变化拒绝恢复。

实施时：

1. 保留旧运行对应的 Git 版本和现有历史产物；不清理 `runs/`，不重写旧结果。
2. 清理后的实现使用独立的新运行目录及明确的控制合同身份；涉及状态结构或语义变化时更新协议版本。
3. 如未来需要旧在线运行迁移，单独设计显式迁移方案；不能放宽摘要检查或把旧记录标记成新实现产物。
4. 新实现不必继续维护原批量实验的运行和报告入口。历史报告可保留为已有静态产物。

P0 的检查与必要合同调整应随首批实现完成，不要求启动真实实验。

## 5. P2：收敛为单一在线实现

### P2-1 消除在线/原生双模式分支

实施状态：已完成，纳入批次 C 验收。

将 `Workflow.online`、bridge 的 `--online` 和 Driver 中的双模式路径收敛为唯一在线路径。在线诊断、阶段写权限和候选检查成为固定规则。

先保持实际提示词、工具权限、候选检查次序和公开字段语义，再删除条件开关。保留错误状态与基础设施中断的区别，不把失败统一转成 skip。

验收：同一模拟响应序列在清理前后产生一致的角色调用、步骤推进、检查计划、接任结果和公开证据范围；比较时排除时间、随机编号等非确定字段。

### P2-2 简化预算和任务选择

实施状态：已完成，纳入批次 C 验收。

- 删除 `PHASE_HOURS`、24 小时/阶段截止、阶段计时及相应持久字段的运行依赖。在线运行继续没有额外总/阶段时限。
- 调整 Broker、Driver 与 OnlineLoop 使用的预算接口，避免删除 `Budget` 后留下失效调用。
- 保留单题 600 秒、角色 500/1000 轮、completion 请求上限、工具限制、服务容量及适用的费用守卫。
- 无期限网络等待继续使用 `None` 等正确形式，不将无穷数写入 JSON 或传入定时器。
- 删除 `freeze_dev_selection()` 及旧 `execution_scope.json/dev_selection.json` 前缀机制，统一使用 `task_limit` 和 `online_task_selection.json`。
- 恢复必须沿用冻结顺序；已消费的调用和角色迭代不能重置。

### P2-3 简化摘要和重复实现

实施状态：已完成，纳入批次 D 验收。workflow 复用限于本次调用，固定定义仍按当前来源读取，未引入跨运行缓存。

| 项目 | 建议 | 必须保留的约束 |

## 6. P3：可选的进一步精简

| 项目 | 可精简范围 | 前提和验证 |
|---|---|---|
| 历史上下文预算 | 分离或删除 `ContextBudget()` 无能力参数时的旧 32768/2048 分支 | 先将仍有效测试迁为显式能力合同；保留当前 Ollama/Qwen 输入审计使用的 tokenizer |
| 数据与镜像范围 | 从校验全部 dev/val/test、冻结 160 镜像，收紧为在线任务集合 | 保留任务、数据和镜像摘要验证；定义新数据合同，不更改历史库存或引入按成绩筛选 |
| `common_tasks` 预留分支 | 当前生产合同固定为空，且没有共同任务评测调度，可删除预留验收逻辑 | 核对所有调用方；保留当前题不退化及已声明的机制判据 |
| 无效命令参数 | 整理被解析但未使用的 `--resume`、bridge `--timeout/--cost-threshold` | 明确命令兼容性变化；保留真实生效的恢复、单题期限和费用规则 |
| 冗余身份表达 | 内部从活动版本统一派生 executor/proposer/parent，减少重复拼装 | 不直接删除持久化身份和跨边界验证；如改记录结构，更新协议 |

只保留在线流程不意味着只支持某一家模型服务。本轮不把 provider 兼容、输入完整性保护或实际加载的 mini 模块列为批量删除对象，也不手工裁剪可演化的候选 Harness。
