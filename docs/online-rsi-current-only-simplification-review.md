## 主要审查结论

- 删除旧 stdout 固定零值汇总、重复文字轨迹、重复宿主计划副本和无用导入／赋值。真实 Docker 测试验证不再生成重复文件，失败路径仍有文字及完整轨迹，归档不会公开历史重复副本。
- 任务执行／完成记录统一完整源码 `code_hash`；旧别名和冲突记录明确拒绝。统一生产测试替身，保留合法第二次 attempt 选择和损坏首次记录的错误分类。
- 已存在任务摘要要求完整身份且禁止错误身份回填；整个摘要尚未生成的合法崩溃窗口可以从已核验宿主结果重建，无需重跑模型。
- 候选记录共用状态校验。非 completed 的 result、completed 的 error、缺失身份、null 或链接记录均拒绝；running 转 interrupted，既有失败不重新调用检查。合法无消息异常仍能保存及恢复。
- 真实 Driver 公开返回缺 record 时，仅从同一已核验 attempt 补齐 record，保留其正确公开源码摘要，不把私有数据带入公开结果。
- 协议只保留 `protocol`；宿主状态与离线报告也应用同一校验。当前版本只有 configuration 或 state 的故障报告仍可生成。旧 `test_seal.json` 拒绝边界保留，只删除恒为真的报告字段。
- 角色 report 只接受非空正文，拒绝旧完成前缀；报告内部文本、Unicode、引号和尾部空格保持。标准 benchmark mini 提交仍通过。
- 父结果不再重复包装成三种摘要，改为显式必需 `parent_hash`；返回前仍校验嵌套宿主 record、任务及评分与反馈一致，Driver 核对父源码路径。`--best-iter/--current-iter` 及其等号形式在宿主和 bridge 明确拒绝；原模板变量从同一父版本派生，proposer 角色审计与恢复身份保留。
- 完整与执行摘要共享一个标准库实现，宿主和容器分别调用；重构前保存的两个固定摘要在自包含测试中保持一致。缺目录、文件路径或链接根均明确报错；子链接不跟随，外层源码校验继续拒绝非法候选。新模块纳入控制清单、improvement 合同及双方启动身份，模块变化不能混用旧恢复记录。
