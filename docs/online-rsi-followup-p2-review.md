# 后续精简四个 P2 项验收

日期：2026-10-18。基点：`523abf8`。执行依据：[后续精简执行计划](online-rsi-followup-simplification-plan.md)。本轮仅实施该计划的四个 P2 项，后续 P3 保留为评估项。

## 分工与最终实现

三个子 agent 均使用用户指定的 **GPT-5.6 Luna / High**，在当前共享工作区分别负责工作流与机制计划、身份与结果布局、正常／恢复的结果构造。子 agent 不提交、不推送、不启动真实推理或完整 Docker 验收。主 agent 审查全部差异，完成协议共享、控制摘要、边界修正、集成测试与本地提交。

1. **恢复格式**：工作流只接受当前完整字段集，删除缺失 `committee_cache` 的旧兼容及空缓存兜底。缓存内容、角色身份、显式恢复授权及累计消耗校验继续执行。
2. **身份与结果**：活动版本必须包含当前控制／模型／服务摘要键；合法显式空身份可以使用，缺键不能当作空身份。决策必须绑定本轮任务、轮次及规范父版本。已发布 accepted 决策必须有完整候选身份和候选检查记录；检查记录绑定完整源码、执行源码、任务、轮次、提案、父版本和检查版本。任务／候选结果只读取正规非链接的数字 `attempt_N` 目录，按数值顺序选择；顶层结果和非数字目录不参与证据选择。
3. **共同校验**：`online_contract.py` 统一在线协议、检查政策版本及共同校验；离线报告仍允许读取当前协议的配置或状态等部分故障产物。`runtime/check_plan.py` 提供纯机制计划规范化，仅接受 `test_path/args/timeout_seconds`，显式拒绝 `entrypoint` 及未知字段。宿主与容器分别调用同一个实现，保留各自的错误边界与输入验证；两个模块纳入控制清单，计划模块另纳入改进任务摘要。
4. **结果构造**：正常与恢复路径共用执行摘要和最终接受／拒绝决策构造；候选身份构造及决策父身份、检查快照核验也共享。正常路径的 `process_status/diagnosis` 与恢复路径原有字段差异保持。消耗结算、持久写入、状态推进、已有摘要核验和未知中断处理继续保留。

当前协议升级为 **online v6**；旧 v2～v5 目录不能直接恢复或重新报告，已有静态报告和运行产物保留，使用相应 Git 版本读取。资源政策 v2、检查政策 revision 2、七步 improvement v6 及实际限制语义保持，不迁移历史身份。

## 主 agent 独立审查与修正

- 去掉子 agent 最初向决策／检查记录额外要求的新摘要字段，要求与当前真实生产者已有格式一致，避免读端要求写端从未生成的字段。修正测试替身的完整父源码摘要与执行摘要混用，并补齐当前生产格式。
- 修正显式空模型／服务身份的缺键漏洞：字典 `get()` 不能区分缺键与合法 `None`，故摘要键必须先确认存在。新增回归覆盖该边界。
- 合并新发布与重放的决策身份检查、正常与恢复的候选身份构造，以及恢复与重放的检查快照绑定。新决策在写入前验证父身份；accepted 重放还要求已检查执行源码与接任源码相同。保留完整源码和执行摘要的不同用途，步骤 6／7 的文档变化不要求与步骤 5 完整源码摘要相等。
- 保留真实崩溃窗口：`checking` 状态可能已保存但 `candidate_identity.json` 尚未写出。恢复仅在完整持久检查、当前 revision 1 计划及已有执行摘要一致性核验之后、首次发布 accepted 决策之前创建缺失身份。已有身份不能覆盖；已发布 accepted 决策缺失身份直接拒绝。检查不通过仍形成普通拒绝，未知中断仍保持中断。
- 修正计划别名拒绝测试，使用新的未冻结工作流验证每个无效输入，避免因已有计划不可变而产生假阳性。核对恢复失败时不会提前写出身份或不可变决策。
- AST 对照确认工作流仅改变恢复与计划规范化两处，Driver 仅改变机制计划验证，报告仅改变在线入口校验；其余源文件差异限定在上述合同、结果布局、构造及绑定范围。评分器、预算、代理、角色权限、工具输出保护与真实上游 agent 未修改。
- 独立执行基点的原机制校验函数，与新实现对照 **18 个合法计划及 10 个无效计划**；规范字段的默认值、边界和拒绝行为一致。另由回归验证本轮主动删除的别名和未知字段兼容。
