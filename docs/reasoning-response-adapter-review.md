# 推理字段动作兼容修复与流式诊断

2026-10-15 用户要求先独立小型流式诊断、保存逐帧响应，再修正普通文字提及格式标记造成的误判，同时继续拒绝多命令块等歧义。原30题实验维持中断，不恢复、不解题、不执行诊断响应中的动作。

## 兼容修复

修改 broker.adapt_response 的一个判定条件：不再要求整个 reasoning 文本只出现一次字符串 mswea_bash_command。普通解释文字提及该名称不等同于一个动作。

其余限制保持：只接受单一 assistant choice、正文为空、finish_reason=stop、没有原生工具调用/拒绝、推理字段有效且别名不冲突、恰好一个完整且非空的 mswea_bash_command 命令块、全文恰好两处三反引号。多块、额外示例代码块、残缺围栏、空块、截断响应仍拒绝。

仅把匹配的命令块复制到返回给 agent 的 content，从派生推理字段删除该块；原始代理响应不改变。此兼容变更不改变第1–3步只读、第4步才可修改代码等阶段权限。

本地历史故障离线回放：调用428和430各只有一个完整块，原先因普通文字重复提及标记被误拒，现可识别；调用429有多个完整块和格式示例，仍拒绝。回放只调用纯解析函数，没有执行命令。

## 独立流式检查

产物目录：runs/proxy-stream-diagnostic-20261015。

- 两次小请求：simple、reasoning_history。均为当前 .env 的 step-5-preview、temperature=0、stream=true、max_tokens=2048；2048仅用于独立小诊断，不改变真实实验64000输出上限，也不改变推理模式。
- 两次分别收到32/23个JSON数据帧，均HTTP200、stop、[DONE]。正文54/76字符，推理252/142字符；用量144/237 tokens。两次均存在独立的 delta.content，短请求没有复现正文缺失。
- 逐帧原文保存为 *.sse，带相对时间的解析帧保存为 *.frames.jsonl，汇总保存为 *.summary.json；保存请求体不含认证头。没有修改代理配置或开启全局请求日志。
- 为减少短请求与故障上下文差异，另独立回放历史调用430的同一份34条消息，保持temperature=0和max_tokens=64000，仅把stream=false改为true。独立180秒健康截止，不执行任何返回动作。该请求与用量单独记录，不冒充实验进度或基线。结果为HTTP200、2813帧、stop与[DONE]完整结束；推理28290字符，正文469字符（首次正文约106.98秒），108.48秒结束，共35854 tokens。正文包含一个只读检查动作。完整上下文也未复现缺失，因此不能把历史异常确定归因于代理聚合或模型上游。

只能观测本地代理对客户端返回的SSE，未取得腾讯上游到插件的原始SSE。若长上下文流式回放复现空正文，可以排除“只有非流式聚合才缺正文”，仍不能仅凭客户端SSE断言是模型本身还是插件流式转换。历史 finish_reason=stop 和正常 usage 也不能证明最终答案已经进入正文。
