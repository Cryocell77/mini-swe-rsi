## 修复与审查

| 边界 | 最终实现 | 验收依据 |
|---|---|---|
| 异常状态 | bridge 保存结果与轨迹后非零退出；适配器同时读取进程状态和 agent 状态 | 真实 Docker HTTP 上下文错误；旧 bridge 进程0但agent失败的兼容回归 |
| 无修改反馈 | 无修改或异常生成确定性事实摘要，避免发送“代码已更新/1.0”给摘要模型；正常完成且修改才进入原始摘要路径 | 正常修改、正常无修改、异常无修改、预算异常后仍有修改四组原生 meta 测试 |
| 候选资格 | 执行是否完成仅影响反馈；保留源码差异、谱系和原有独立评测流程 | 预算终止但已修改的候选继续进入原生 benchmark；没有新增 Submitted 晋升门槛 |
| 消息计量 | `mini-text-bash-v2` 保留正文和一份 reasoning_content，去除供应商副本；实际发送与字符计量、日志使用同一规范化消息 | 模拟端点检查 wire 与计量相同；真实超限拒绝；旧轨迹离线复核 |
| 归档暴露 | 权威归档用于原生选择；容器只读挂载公开冻结副本，源码逐字保留，其他证据按文件白名单复制 | 排障副本、trajectory 配置、host_result/attempt/评分资产不可见；候选源码摘要一致 |
| 恢复与回放 | 协议版本独立冻结；旧实验不能按新协议恢复；回放只消费模型/工具操作事件 | 旧协议提前拒绝；恢复不重复提案；原行为回放与父版本对照测试 |

主 agent 审查第一版时要求两项修正：不能按普通配置名或扩展名限制候选源码；必须通过真实 bridge 测试异常状态，而非只用 driver fixture。两项均已落实。主 agent 另新增 `test_sica_runtime.py`，让真实 mini 在容器内通过命令修改 RW 候选配置，随后由原生 SICA 加载该归档版本执行下一轮改进，验证继承后的配置实际进入模型请求。

源码 SHA 检查不将未使用的改动自动等同于行为收益；原有父版本行为回放与有效性门槛保留。

## 验收边界

**工程边界修复验收通过，RSI 有效性尚未重新测量。** 容器继承测试的模型回复与选择分数是明确的 fixture，不能当作模型自改进收益。消息预算仍按规范化 JSON 字符计，后端实际最大上下文能力没有由本轮测试确定。成功修改的模型摘要仍可能判断失误，任务收益须依赖独立评分和原有门槛。

修复后实验必须使用新运行目录，不能覆盖或续跑旧协议实验。提交包含此前尚未入库的项目实现及本次修复，排除 `.env`、数据、运行产物和依赖环境；仅提交本地分支，不自动推送。
