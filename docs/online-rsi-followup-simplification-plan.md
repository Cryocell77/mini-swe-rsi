## 三个 P1 项的实施步骤

### P1-1：评分器只保留当前评分入口

1. 核对当前调用方：`Driver.score()` 固定生成 `operation=score` 并携带冻结镜像信息；项目无 `image` 任务生产者。
2. 删除构建镜像的辅助函数和分支。未知操作仍明确拒绝，不能把 `image` 静默当作 `score`。
3. 保留 `frozen_image()`，含缺失时按不可变 digest 获取、身份及架构校验、可变标签拒绝。保留 `direct_assets()`、官方 `run_instance()`、容器隔离、空补丁与已知失败分类。
4. 测试覆盖未知／已删除操作拒绝，以及有效评分在空补丁、正常结果和已知失败情况下保持原行为。不得调用真实推理或修改已有任务镜像。

### P1-2：清理工作流无用赋值

1. 删除 `execute()` 内未消费的 `op`，实际别名解析继续由 `dispatch()` 负责。
2. 委员会返回身份在不消费的调用处明确丢弃；保留缓存条目、恢复绑定与角色事件中的身份。
3. 其他赋值只有确认不承担验证或副作用才删除；不移除回调约定所需参数，不扩大到角色映射或状态格式重构。
4. 使用既有角色、别名、委员会、缓存恢复及结构化提交测试验证，避免新增只镜像实现的测试。

### P1-3：删除预算占位信息

1. 删除两个 `fileview_regeneration_*` 字段，检查生产代码没有消费者。
2. 对照基点，删除这两个键后的预算字典必须完全一致，包含角色迭代、单题期限、请求次数、工具声明／有效超时、输出保护、模型上下文及输出容量。
3. 本项不改变实际资源政策语义，保留在线 v5、资源政策 v2、检查 revision 2、七步 improvement v6。预算源文件及工作流摘要改变，由既有控制清单拒绝混用旧实现；不迁移旧运行。
4. 同步当前说明；历史验收保留当时版本与结论。
