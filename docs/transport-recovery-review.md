## 已观察到的原因

- 代理三次等待约 900 秒后返回 finish_reason=error、无 usage 的 completion，而非 HTTP 500，原只检查 500 的暂停器没有触发。
- bridge 传入 timeout=None，LiteLLM 实际回落 600 秒；角色已退出，但宿主仍无限等待旧请求。单并发状态锁被等待占有，后续请求排队。
- 模型多次动作格式失败，评审组中途失败后丢失整组返回，引起重复调用。
- 保存现场时原工作流已完成两步、在第三步，角色计数18。活动编码角色已创建 minisweagent/tools/__init__.py；该工作副本必须保留。

## 修复边界

bridge 的可序列化模型配置仍记录 timeout=None，真实 SDK 请求边界显式注入 httpx.Timeout(None)，避免隐式600秒且不破坏官方模型配置/轨迹序列化。有限宿主剩余时间仍原样传递。归档 agent/model 类与原 SICA 角色/步骤源码不改。

宿主可选 transport_policy.json 冻结请求健康策略。本次单次请求 watchdog=900秒，HTTP500、网络超时、错误 completion、缺失 usage 均持久暂停并拦截后续模型、工具和候选任务，不自动重试。900秒是基础设施健康等待期限，超时记为代理故障，不是实验总预算、角色轮数限制或模型题目失败。原任务600秒、500/1000角色迭代、输出/上下文容量保持原合同。

provider I/O 不占有状态锁；仍保留单模型并发。超时后尽力取消本地连接，远端取消不保证；迟到结果不能交给 agent，能取得的用量另记。未知用量不记为零费用。

评审成功结果按提案全文、上下文、父版本、模型和源码执行摘要缓存。只有完全相同输入与源码的成功结果才能复用；源码变化后历史评审不能批准新版，失败评审不能充当成功。
