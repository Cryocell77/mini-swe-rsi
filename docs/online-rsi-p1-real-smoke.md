## 已观察到的失败链路

1. 首次任务回复在 THOUGHT 中包含多个说明性代码块，再附实际动作块。适配器按既有严格规则拒绝多个/不支持的 fence，连续拒绝导致 RepeatedFormatError。这不是评分基础设施错误。
2. 模型将改进集中在动作格式配置，完成两步诊断、两轮评审和候选实现，随后进入第 5 步。
3. 第 5 步自行编写的 `/tmp/run_integration.py` 本地检查反复执行模拟 `echo hello` 并输出记录，没有正常结束。进程返回 137；主 agent 在运行期间只读检查到对应工具容器 `State.OOMKilled=true`，确认触发内存限制。
4. 该工具输出为 **130,708,079 字符**。随后模型请求的 content 共 **130,801,226 字符**，序列化原消息约 1.334 亿字符；服务声明上下文容量为 1,000,000 tokens，当前模型没有可验证本地 tokenizer，发送前不执行 token 估计保护。
5. 这次请求最终返回 HTTP 500，无可用 usage。超长观察与 HTTP 500 的先后关系有记录，但没有服务端日志，不能断言 HTTP 500 的内部根因，也不能把字符数直接换算成实际 prompt tokens。
6. 框架将改进进程异常退出标记为 OnlineInterrupted，保持 H0，不把失败当作 skip 或接任成功。主 agent 准备停止异常运行时进程已自然结束，未实际发送终止信号；没有人为重建用量或追加请求。
