## 不能只归因于模型能力的三处适配因素

**元改进提示发生语义退化。** `runtime/bridge.py:38`把原SICA的“尽早调用元改进推理结构”替换成“使用bash检查归档”。原来指向进入改进推理过程，现在额外强调检查归档。缺少原SICA对应工具时确实需要适配，但这不是语义等价替换，也没有恢复原规划结构。它可能加强阅读倾向；本次没有提示词对照实验，不能认定单独因果。

**候选与历史版本身份不够清楚。** 原SICA本身先copy父版本到agent_1，再挂载包含agent_1的整个归档（vendor/sica/runner.py:777、832）；因此agent_1可见不是新增复制错误。当前公开视图将其冻结为只读副本，workdir才是实时可写候选，且没有在任务中清楚标明agent_1是未评测候选、并非已有成功版本。模型实际误判了这个身份。该问题不同于“排障资产泄露”，属于归档语义与任务协议不清晰。

**30步合同没有进入任务说明。** bridge强制step_limit=30（runtime/bridge.py:72），实际初始system/user提示没有明确调用预算和剩余步数提示。原SICA的500/1000迭代与当前30调用不是同一合同。预算用尽是直接终止条件；预算未告知可能影响行动分配，但不能由此断定扩大到60步必然成功。
