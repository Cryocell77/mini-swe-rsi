## 原因与修复边界

上一次真实实验的离线测试桩第一次抛出 FormatError，此后永远返回零费用的 `echo hello`。测试调用 `DefaultAgent.run()`，却没有最终退出消息，也未设置步数上限。正常动作会清零连续格式错误计数，费用也始终为零，因此原脚本的后置断言无法执行。它不断追加消息、打印日志，最终 OOM；约 1.307 亿字符的工具观察又进入后续模型请求，随后服务返回 HTTP 500。

本次不改写上游 mini 的循环、SICA 七步定义、角色迭代额度或候选验收标准；不增加全局或阶段时限。

- 为协调者和可执行本地检查的角色补充测试约束，并要求转交给委派任务：测试单次恢复使用有限次 `step()`；测试完整 `run()` 必须让桩产生显式退出，同时使用有限 `step_limit` 兜底，并校验具体退出状态。`LimitsExceeded` 不能冒充通过。
- 在线改进 shell 的 stdout/stderr 改为分块收集。正常输出保持原样；超过 300,000 字节时返回明确索引及首尾预览，完整输出留在宿主文件中。
- 收集到超过 8 MiB 的输出时销毁当前工具沙箱，包括命令的子进程，返回 `ToolOutputLimitExceeded`。此时只保存 8 MiB 前缀，明确记录 `complete=false`、已保存/观察到的字节数及前缀 SHA256；不宣称保存了完整输出。沙箱 `/tmp` 状态会丢失，并明确告知模型。
- 工具输出目录只读挂载到新的工具沙箱 `/home/agent/tool_outputs`，模型可通过普通 shell 按需读取小片段；不开放父级日志、流程状态或凭证。
- 原有 600 秒命令超时继续有效；超时也清理工具沙箱。benchmark 作答与独立评分的输出处理保持原样。
- 新处理模块纳入在线控制文件摘要，资源上限纳入冻结预算契约；不把字节上限说成 token 估计。

提示指引不能保证模型生成的任意脚本都会正确终止；本次实际循环模式另有工具层的硬限制兜底。无输出的任意错误脚本仍受原有工具超时和容器资源隔离约束。
