# 五题开发集能力诊断

2026-10-12，检查版本 `2b0f9ffc028b38992cb47b4e96e4af5adb09007d`。用户授权直接在数据集上小规模测试；本轮新求解五道开发题，没有运行全量基线、演化搜索、验证集或测试集。

**独立评分通过 1/5；五题均写出了文件，其中三题修改了业务源码。** 当前模型具备部分真实修复能力，但有限预算下的任务推进、上下文管理和输出协议匹配仍有问题。这不能作为 Harness 自改进或 RSI 有效性的证据。

## 固定实验条件

按已校验 dev 清单顺序取前五题，任务列表在模型调用前冻结，不按历史分数挑选。运行官方固定 mini 的 H0 归档，通过修复后的 `mini-text-bash-v2` 与生产 `Driver.task_retry` 求解、收集补丁并交由独立 SWE-bench 评分。模型使用 `.env` 的 `qwen35-4b-agent:latest`，开始与结束服务公布的模型、权重摘要及推理参数相同。

每题 30 次调用、600 秒，命令 60 秒，模型单次输出上限 2048 tokens，上下文为规范化 JSON 的 60,000 字符，模型并发 1。诊断整体上限 60 分钟，同时受旧实验首次真实调用起 24 小时截止时间约束。没有向求解者导入旧答案、参考补丁或私有评分测试，也没有在中途改变配置。

## 失败与成功的具体证据

**输出协议不匹配是本轮新增的明确发现。** 共 11 次格式错误均为：服务返回正文 `content` 为空，完整 bash 动作块仅出现在 `reasoning_content`；官方 mini 从正文提取动作，识别到 0 个动作。它们分布于四道题，Django 单题占 8 次。这些回复的 `finish_reason` 为 `stop`，不是输出达到 2048 tokens 后被截断。格式纠正消耗调用次数并增加历史长度；当前证据不能确定服务为何将动作放入推理字段。

这与此前的“供应商重复推理字段计量”缺陷不同。本轮规范化去重仍有效；新发现涉及返回回复的动作字段与 agent 所需文本协议不一致。保留单份推理字段不等于 agent 能从该字段提取动作。本轮没有通过自动执行推理字段中的命令、禁用推理或扩大上下文来改变实验条件。

**上下文合同仍频繁阻断运行。** Astropy、Seaborn、Flask、Xarray 最后被拒绝输入分别为 60,630、60,223、63,183、60,921 字符。Django 的最后一次输入为 53,683 字符，因调用次数耗尽结束。读文件、生成多个复现脚本、反复自测和格式纠正都累积历史；本轮没有测量这些因素各自对失败的因果贡献。

**Seaborn 形成了有效补丁。** 模型修改 `PolyFit._fit_predict`，联合过滤 x/y 缺失值；独立评分中一个目标失败测试转为通过，两个原通过测试继续通过。该结果证明当前组合能在真实任务中形成通过既定测试的修改；不代表不存在未覆盖的回归，也不证明改进 Harness 的能力。

**Flask 存在题面与评分接口差异。** 模型新增 `mode` 参数并用于打开配置文件；题面也提出 file mode 参数并展示 `mode` 示例。但独立评分测试调用 `text` 参数，因 `unexpected keyword argument 'text'` 失败，18 个原通过测试保持通过。按冻结评分合同本题计 0；这份结果不能单独解读为“完全没有实现二进制读取思路”。模型的方案与评分要求不兼容，且其完整边界正确性没有由本轮确认。

**Xarray 补丁有真实实现错误。** 模型在公开 `concat` 入口增加 `ignore_missing` 参数，却在 `_dataset_concat` 使用未定义的同名变量，没有完成参数传递。评分出现 `NameError`，两个目标测试未通过，并引入 17 个原通过测试回归。这是模型生成的任务补丁错误，区别于宿主框架的实现缺陷。

Astropy 和 Django 仅产生复现脚本，目标失败测试均未修复。不能将“非空补丁”统一当作“已经修复业务源码”。

## 消耗、隔离与结论边界

- 实际耗时 **727.0 秒，约 12.1 分钟**。
- **117 次模型调用，106 次已执行工具命令，953,634 total tokens，其中 857,554 cached tokens**；0 次未计量调用，0 次模型请求服务错误。token 数包含历史输入重复计费，不能理解为新生成文本量。
- 生产源码、运行桥接与 vendor 摘要未变，五题加载同一 H0 源码。模型身份前后相同。旧运行 5,668 文件封存清单未改变。
- 本轮是五题的新求解诊断，不是完整 dev30 基线。val/test 均未运行；没有提案、候选晋升或 RSI 搜索。
- 货币成本未估算；内部 `cost_estimate=0` 占位值不作为免费运行的证据。

对“代码问题还是模型问题”的判断需要进一步细分：框架求解、补丁收集和独立评分链路正常；模型具备部分编码能力，也生成了存在实现错误的补丁；同时仍有输出协议兼容性与上下文合同造成的阻断。因此不能把剩余失败统一归因于模型本体能力不足。优先排查这些协议与资源边界，再用单独标记的实验比较，才能更清楚衡量开放式改进能力。

五题只提供初步诊断，不支持总体成功率、修复前后收益、持续递归能力或更强模型必要性的结论。
